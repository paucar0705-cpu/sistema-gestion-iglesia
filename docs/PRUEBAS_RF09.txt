Pruebas automatizadas (usan una base temporal; no tocan data/iglesia.db):
  node --test --test-concurrency=1 "test/*.test.js"

Prueba manual en Windows PowerShell:
1. npm install
2. Copy-Item .env.example .env (si aún no hay .env)
3. npm run db:reset  (ATENCIÓN: borra y reconstruye la BD LOCAL; omitir si ya tienes datos que conservar)
4. npm run dev
5. Abrir http://localhost:3000 y entrar con los usuarios de prueba del README.

Comprobar:
- Administrador: entra a los 4 reportes y descarga sus Excel.
- Pastor / Secretario: entran a miembros, asistencia y ministerios; ingresos y su Excel dan HTTP 403.
- Tesorero: entra a miembros e ingresos; asistencia y ministerios dan HTTP 403.
- Coordinador: la sección Reportes da HTTP 403.
- Fechas de asistencia e ingresos filtran correctamente, incluso al exportar.
- Fechas inválidas, rangos invertidos y filtros repetidos dan HTTP 422.
- Abrir los archivos .xlsx en Microsoft Excel:
  * Comprobación automatizada con Microsoft Excel: los cuatro archivos se abrieron
    correctamente, fueron reconocidos como válidos y sus filtros funcionaron.
  * Revisión manual: la usuaria abrió el reporte de ingresos y confirmó que funciona
    correctamente.
  * Pendiente: abrir manualmente los reportes de miembros, asistencia y ministerios.
